◆ ctr_cloud_data_encode_cb

typedef int(* ctr_cloud_data_encode_cb) (zcbor_state_t *zs, void *user_data)

Callback encoding the CBOR payload of a data message.

Encodes the payload of a data packet (UL_UPLOAD_DATA) with the zcbor encoding state zs, which writes directly into the transfer buffer of the cloud subsystem. The packet header is already in place and cannot be overwritten, and the callback cannot write behind the end of the buffer: when the message does not fit, zcbor reports ZCBOR_ERR_NO_PAYLOAD and the message is not sent.

The callback must close every container (map, list) it opens.

The state has stop_on_error enabled, so the callback does not need to check the result of every put call. The first error is kept and nothing is written after it.

The callback runs in the caller's thread with the cloud lock held. Calling ctr_cloud_send_data(), ctr_cloud_send(), ctr_cloud_send_data_cb(), ctr_cloud_downlink() or ctr_cloud_firmware_update() from it fails with -EDEADLK; other blocking cloud calls (e.g. ctr_cloud_wait_initialized()) may deadlock. Do not take a lock whose holder may call the cloud API.

It may be called at most once per send, but a send is not guaranteed to call it exactly once, so side effects (for example sequence numbers) should be kept outside of the callback or be idempotent. The message must fit into the transfer buffer minus the 9 byte packet header. The helpers ctr_cloud_cbor_free(), ctr_cloud_cbor_len(), ctr_cloud_cbor_put_raw() and ctr_cloud_cbor_put_key_ts() are meant to be used from the callback.

Return 0 on success or a negative errno. Avoid -EAGAIN, -ETIMEDOUT, -EDEADLK and -EPERM: the value is passed through unchanged and cannot be told apart from the errors of ctr_cloud_send_data_cb() itself.

Parameters
zsEncoding state positioned behind the packet header.
user_dataUser data passed by the caller of the send function.
Return values
0Success, the message is complete.
negativeError (negative errno) which aborts the send and is returned to the caller of the send function unchanged. Nothing is sent.
positiveNot allowed, reserved for the cloud subsystem; treated as -EINVAL.

int ctr_cloud_cbor_put_raw ( zcbor_state_t *  zs,

Insert an already encoded CBOR value into the payload.

Writes no key. cbor must be exactly one complete CBOR data item (a whole map, list, ...); this is not validated. The item is counted in the element count of zs like any other encoded element.

On lack of space the zcbor state is put into the ZCBOR_ERR_NO_PAYLOAD error, so the failure cannot be missed even if the return value is ignored (the send then fails with -ENOSPC).

Parameters
zsEncoding state passed to the callback.
cborEncoded CBOR value.
lenLength of the encoded value in bytes.
Return values
0Success.
-EINVALzs is NULL, or cbor is NULL or len is zero. In the latter case nothing is written, but the state is put into the ZCBOR_ERR_WRONG_VALUE error, so the failure cannot be missed.
-ENOSPCNot enough space (the state is put into the ZCBOR_ERR_NO_PAYLOAD error), or the state already holds that error. Nothing is written.
-EBADMSGThe state already holds any other error. Nothing is written.

◆ ctr_cloud_downlink()

int ctr_cloud_downlink ( k_timeout_t  timeout)

Download pending data from the cloud.

Downloads one downlink message and processes it (session, time, configuration, data for the callback of ctr_cloud_set_callback(), shell commands, firmware), uploading a response when the message requires one. When the cloud has more messages, another download is scheduled on the cloud work queue.

timeout is one deadline for waiting for the cloud lock and for the download. Uses soft timeout: when timeout expires, the underlying LTE operation completes gracefully before returning. The timeout applies only to the initial download - any required response upload uses K_FOREVER.

Parameters
timeoutDeadline for the lock wait and the download.
Return values
0Success, also when there was nothing to download.
-EPERMctr_cloud_init() has not completed.
-EBUSYtimeout is K_NO_WAIT and the cloud lock is taken.
-EAGAINThe deadline expired while waiting for the cloud lock.
-EDEADLKCalled from inside an encoder callback.
-ETIMEDOUTThe download timed out.
<0Another transfer error, or the message could not be processed.

◆ ctr_cloud_init()

int ctr_cloud_init ( struct ctr_cloud_options *  options)

Initialize the cloud subsystem and start connecting in the background.

Stores options (not copied, the structure must stay valid), starts the cloud work queue and returns without waiting for the cloud: the work queue creates the session and uploads the decoder, the encoder and the configuration, retrying all but the configuration until they succeed. Use ctr_cloud_wait_initialized() to wait for it. Call once; a call that failed leaves the subsystem unused and can be repeated.

Parameters
optionsHashes and optional decoder and encoder of the application.
Return values
0Started.
-EINVALoptions is NULL, or the claim token is not 32 hex digits.
-EPERMThe claim token is not set.
-EALREADYAlready started by a previous successful call.
<0Another error reading the device information or initializing the transfer layer.

Send data to the cloud with timeout.

Copies buf (the encoded payload) into the cloud transfer buffer behind the data packet header and sends it. Call only after ctr_cloud_init() has succeeded.

timeout is one deadline for waiting for the cloud lock and for the transfer; the transfer gets the time left. Uses soft timeout: when timeout expires, the underlying LTE operation completes gracefully before returning. The timeout signals "finish when you can", not an immediate abort.

With CONFIG_CTR_CLOUD_SPOOL, a message that is not sent because the transfer fails (or, for ctr_cloud_send_data_cb(), because the deadline expired after encoding) stays in the spool and goes out with a later successful send; the return code does not tell whether the message was queued, so a retry by the caller may duplicate it.

-EDEADLKCalled from inside an encoder callback.

◆ ctr_cloud_send_data_cb()

int ctr_cloud_send_data_cb ( ctr_cloud_data_encode_cb  cb,
void *  user_data,
k_timeout_t  timeout 
)

Encode a data message with a callback and send it to the cloud.

Waits for the cloud lock, then lets cb encode the CBOR payload directly into the cloud transfer buffer behind the data packet header, so the caller needs no message buffer of its own. The callback is called only once the transfer buffer is free, so the data reflect the moment of sending.

timeout is one deadline for waiting for the cloud lock and for the transfer: the time left after the lock is acquired and the payload is encoded is passed to the transfer layer, which applies it to each packet exchange, so a fragmented message can take longer than timeout. If the deadline expires while waiting for the lock, the callback is not called (-EAGAIN); if it has expired before the transfer can start, nothing is sent (-ETIMEDOUT); K_NO_WAIT therefore never sends.

If encoding fails, nothing is sent. Test the result with ret != 0; positive values are reserved.

With CONFIG_CTR_CLOUD_SPOOL, a message that is not sent because the transfer fails (or, for ctr_cloud_send_data_cb(), because the deadline expired after encoding) stays in the spool and goes out with a later successful send; the return code does not tell whether the message was queued, so a retry by the caller may duplicate it.

Parameters
cbEncoder callback, see ctr_cloud_data_encode_cb.
user_dataPassed to cb.
timeoutDeadline for the lock wait; the rest is the transfer timeout.
Return values
0Sent.
-EINVALcb is NULL, the callback returned a positive value or encoded an empty payload.
-EPERMctr_cloud_init() has not completed.
-EAGAINThe deadline expired while waiting for the cloud lock; the callback was not called.
-ETIMEDOUTThe deadline expired before the transfer could start, or the transfer timed out.
-EDEADLKCalled from inside an encoder callback.
-ENOSPCThe payload does not fit the transfer buffer.
-ENOMEMNot enough zcbor backup states (raise CONFIG_CTR_CLOUD_ENCODE_ZCBOR_STATES).
-EBADMSGThe payload is not valid CBOR.
<0A negative error returned by cb, or another transfer error.
